# v2 UI/UX 설계서 — Coinbase식 패턴으로 다시 쓰는 화면

- 작성: 2026-10-26 · 상위 문서: [프로그램 계획서](2026-10-26-v2-program-plan.md) §4 1·4단계
- 적용 저장소: `My_macro_dashboard_v2` `frontend/`. API 경로는 바꾸지 않는다([docs/API.md](../API.md)가 그대로 계약)

## 0. 목적과 비목적

**목적.** 지금 17개 경로를 Coinbase 웹·앱이 쓰는 패턴 — 적은 탭, 큰 숫자, 자산 행 목록, 격자 없는 단일 라인 차트, 상세 페이지 하나로 모든 자산을 설명 — 으로
다시 쓴다. 보는 사람이 "지금 무엇이 중요한가"를 홈 한 화면에서 읽고, 궁금한 값은 두 번 안에 상세로 들어간다.

**비목적.** Coinbase의 색·로고·문구를 모방하지 않는다(패턴만). 휴대폰 접속 경로를 만들지 않는다 — 반응형으로 만들되 접속은 PC 터널만(ADR 0016·0019).
계산을 화면으로 옮기지 않는다(ADR 0004 — 화면은 표시와 입력만).

## 1. 기술

| 유지 | 추가 | 보류 |
|---|---|---|
| Next.js 16 · React 19 · TypeScript · Tailwind 4 · Recharts 3 · vitest | **Radix UI primitives**(Tabs·Dialog·DropdownMenu·Tooltip·Toast·VisuallyHidden) — 키보드·포커스·ARIA를 직접 다시 만들지 않기 위해. 설치 때 npm GA 버전을 확인해 고정 | `lightweight-charts`(캔들·거래량) — 한국 OHLCV가 쌓인 뒤 결정. `@playwright/test`(e2e) — 4단계에서 승인 |

Radix 외 새 의존성은 이유를 먼저 적고 승인받는다(사용자 규칙).

## 2. 계층(ADR 0004)과 폴더

```
src/app/(app)/…                라우트(서버 컴포넌트 기본). 데이터 fetch는 여기서, 그리기는 components로
src/components/ui/             Radix 감싼 기본 조각(Button·Tabs·Dialog·Tooltip·Toast·Skeleton)
src/components/patterns/       화면 패턴(AssetRow·Hero·StatTile·DetailLayout·DataTable·ProvenanceBadge·EstimateBadge·Empty·ChangeChip·Sparkline)
src/components/charts/         Recharts 래퍼(LineChart·AreaChart·BarChart·Heatmap) — 축 규칙을 여기서 강제
src/components/screens/<탭>/   화면 조립(그리기만)
src/hooks/                     자동 갱신·범위 선택·검색 등 상태 훅
src/lib/                       순수 함수(서식·단위·거래소 달력·색 선택·빈값 판정) — 테스트 대상
src/lib/api/                   API 클라이언트(경로는 docs/API.md와 1:1, endpoints.test.ts가 대조)
```

## 3. 디자인 토큰

- **색(의미 토큰)**: `bg`·`surface`·`surface-2`·`border`·`text`·`text-2`·`text-3`·`accent`·`up`·`down`·`warn`·`neutral`·`focus`. 라이트·다크 두 벌.
  액센트는 하나만. `up`·`down`은 상승·하락 전용이고 **다른 뜻으로 쓰지 않는다**. 조합은 dataviz 팔레트 검증기(`validate_palette.js`)를 통과한 값을 기록으로 남긴다(PRINCIPLES "계열 색").
- **타이포**: 본문 1단(15~16px), 숫자는 `font-variant-numeric: tabular-nums`. 히어로 숫자 36~44px, 카드 숫자 20~24px. 단위는 숫자 옆에 작은 글자로, 숫자 안에 넣지 않는다.
- **숫자 서식**(기존 `lib` 규칙 승계): 값 없음은 `—`(0으로 채우지 않음), 변화율은 부호와 소수 둘, 큰 금액은 단위(T·B·억·조)와 함께 — 같은 화면의 타일과 차트는 같은 단위.
- **간격** 4pt 격자, 카드 라운드 12px, 그림자는 쓰지 않고 1px 경계로 구분. **모션** 150ms 이하, `prefers-reduced-motion`이면 없음.
- **차트**: 격자 없음, 축은 끝값 두 개와 기준선(0이 의미 있는 계열만), 호버 툴팁에 날짜·값·출처. Y축 범위는 데이터 범위(PRINCIPLES "축부터 정직"), 자릿수가 다른 계열은 패널을 나눈다.

## 4. 정보 구조 — 다섯 탭과 더보기

| 탭 | 새 경로 | 들어가는 기존 화면(옛 경로 → 리디렉션) |
|---|---|---|
| 홈 | `/` | 오늘의 국면(`/regime` 요약) · 모의매매 순자산(미국·한국) · 시장 카드 행(`/macro` 카드) · 알림 요약(`/alerts`) |
| 시장 | `/markets`, `/markets/macro`, `/markets/liquidity`, `/markets/sectors`, `/markets/correlation`, `/markets/cot`, `/markets/krx`, `/markets/regime` | `/macro` `/liquidity` `/sector` `/correlation` `/cot` `/krx` `/regime` |
| 기관 | `/institutions`, `/institutions/13f`, `/institutions/style`, `/institutions/consensus`, `/institutions/scorecard` | `/institutions` `/style` `/consensus` `/scorecard` |
| 한국 | `/korea`, `/korea/radar`, `/korea/futures`, `/korea/public` | `/radar` `/krx`(선물 부분) 공공데이터 |
| 모의매매 | `/paper`, `/paper/us/*`, `/paper/kr/*` | `/paper`(7탭) → `/paper/us/*`. `/paper/kr/*`는 2단계 |
| 더보기 | `/more`, `/more/alerts`, `/more/account`, `/more/status`, `/more/connections` | `/alerts` `/account` `/status` `/connections` |

- 상세 페이지는 두 종류만 둔다: **지표 상세** `/markets/i/<지표 id>`(매크로 카드·FRED 시계열·섹터 ETF 등)와 **종목 상세** `/s/<시장>/<코드>`(미국 티커·국내 코드). 모든 자산 행·카드가 이 둘로 들어간다.
- 옛 경로는 `next.config`의 redirects로 301. `access.test.ts`는 새 경로를 `AccessPolicy` 범주(공개·회원·유료·운영자)에 대조한다 — `/paper/*`는 운영자 전용.
- 통합 검색(⌘K): 종목(이름·티커·코드)·기관(13F)·지표(카드 이름·FRED id)·메뉴. 결과는 위 두 상세 또는 메뉴로 이동.

## 5. 화면 패턴 여섯

| 패턴 | 구성 | 데이터 계약 | 빈값·추정·오래됨 |
|---|---|---|---|
| 자산 행 `AssetRow` | 아이콘/이름·보조 텍스트 · 스파크라인(선택) · 값 · 변화 칩 · 배지 | `{id, name, sub?, value, unit?, change?, changePct?, spark?: number[], asOf, delayMin?, source, isEstimated?, isProxy?, isStale?}` | 값 없음 `—`, 변화 없음은 칩 생략(0.00% 아님), `isStale`면 회색 시각 배지 |
| 히어로 `Hero` | 큰 값 · 라벨 · 변화 칩 · 기간 탭 · 한 줄 판정 글 | 값 + 기간별 변화 + 판정 문장(백엔드가 준 글) | 판정은 글로(색·선만으로 전달 금지) |
| 통계 타일 `StatTile` | 라벨 · 값 · 단위 · 보조(백분위·표본) | `{label, value, unit, note?, isEstimated?}` | 표본 부족이면 `—`와 사유 |
| 상세 레이아웃 `DetailLayout` | 히어로 → 차트(기간 탭) → "정보"(출처·지연·마지막 수집·정의) → 관련(뉴스·연관 지표·보유 계좌) | 시계열 + 메타 | 기간 탭은 저장 구간을 넘지 않음(PRINCIPLES) |
| 표 `DataTable` | 밀도 높은 표, 열 정렬·고정 머리, 행 클릭 → 상세 | 열 정의 + 행 | 열 단위 `—`, `isProxy` 셀 표시 |
| 상태 배지 | `ProvenanceBadge`(수집 시각·지연·출처) · `EstimateBadge`(`isEstimated`·`isProxy`) · `StaleBadge`(`isStale`·이어받은 값) | 메타 플래그 | 플래그가 있으면 **반드시** 보인다 — 숨기는 옵션 없음 |

## 7. 화면별 요지

- **홈**: ① 오늘의 국면 히어로(판정 라벨·세 신호 타일·"3일 확정" 배지) ② 모의매매 히어로(미국·한국 탭, 네 계좌 순자산 행, 한국은 2단계 전 '준비 중') ③ 시장 카드 행(매크로 카드 전부를 자산 행으로, 실시간·지연 배지) ④ 알림 요약 ⑤ 데이터 저장소 상태 한 줄(실패 태스크 수).
- **모의매매(미국)** `/paper/us`: 개요(네 계좌 행 + 기간별 순자산 차트, 계좌 클릭 → 계좌 상세) / 기관 선정 / 보유·체결(표) / 결정 로그(카드: stance·노출·주문·근거, 숫자 근거 검사 배지는 3단계) / 복기 / 프레임 / 메모 / 설정(규칙 계좌 영향 키는 ConfirmDialog). 기존 7탭의 기능을 빠뜨리지 않는다 — 이식 전에 기능 목록을 표로 만들어 하나씩 지운다.
- **지표 상세**: 히어로(값·변화·판정 글) → 차트(1·3·5·10년, 저장 구간 안) → 정보(출처·지연·마지막 수집·정의·임계치는 '참고') → 연관 지표.
- **종목 상세**: 히어로(종가·변화·거래일) → 차트 → 스코어카드 타일(백분위 + 원자료) → 13F 보유 기관 / 수급(국내) → 뉴스 → 모의매매 보유 여부.
- **표 화면**(13F·수급 레이더·COT): `DataTable` + 필터 칩. 행 클릭 → 상세.

## 8. 접근성·성능

- 대비 4.5:1, 포커스 링, 키보드로 탭·검색·표 이동, 색만으로 뜻 전달 금지(판정은 글, 상승·하락은 칩에 부호).
- 라우트는 서버 컴포넌트, 차트·검색·표 정렬만 클라이언트. 응답 캐시는 백엔드 `ComputedCache` 그대로. 자동 갱신 간격은 기존 훅 승계.

## 9. 이식 순서와 완료 정의(DoD)

1. 1단계: 토큰·셸·공용 컴포넌트 → **홈** → **모의매매(미국)**. 끝에 토큰·셸 시안 사용자 승인.
2. 4단계: 시장 → 기관 → 한국 → 더보기 → 옛 화면 제거 → e2e.

화면 하나의 DoD:
- [ ] 기존 화면의 기능 목록을 전부 덮었다(표로 대조)
- [ ] 네 상태(없음·일부 실패·추정·오래됨) 렌더링 테스트
- [ ] 축·단위·빈값·배지 PRINCIPLES 체크리스트 통과
- [ ] `endpoints.test.ts`·`access.test.ts` 통과, 옛 경로 리디렉션
- [ ] 라이트·다크 둘 다 확인, 1280px·768px 두 폭 확인

## 10. 사용자 결정이 필요한 것

- 액센트 색(검증기를 통과한 후보 2~3개를 1단계 초에 보여 드림), 기본 테마(시스템 따름 권장)
- 통합 검색 범위(종목·기관·지표·메뉴 네 가지로 시작 권장)
- 메뉴 라벨 언어(한국어 유지 권장, 티커·id는 영어)
